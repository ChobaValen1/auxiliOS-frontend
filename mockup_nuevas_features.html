1

Comparativo período anterior en KPIs

Cada KPI muestra el delta vs el mismo período justo anterior. Semana actual vs semana pasada, mes actual vs mes pasado. Se ve en verde si mejoró, rojo si empeoró.

Cómo funciona: por cada carga de datos del período actual (hoy/7días/mes), se dispara en paralelo la misma query con las fechas del período previo. Se calcula ((actual − anterior) / anterior) × 100. El badge cambia de color según delta > 5% (verde), < −5% (rojo), o entre medio (gris).

Ojo: el primer período (sin histórico previo) muestra el badge en gris con "Sin comparación disponible".
2

Historial de rendiciones (admin/supervisor)

Hoy la rendición es una acción "de un solo shot" — el chofer la carga y desaparece. Falta la vista donde el admin puede revisar, aprobar o marcar diferencias. Todos los cambios quedan auditados.
Menú Admin → Rendiciones
FechaChoferDeclaradoEsperadoΔEstado
01/07Ivan R. $45.200$45.200 $0 Pendiente
30/06Ivan R. $38.100$40.500 −$2.400 Con diferencia
29/06Juan P. $52.800$52.800 $0 Aprobada
28/06Juan P. $47.200$45.500 +$1.700 Aprobada
Cómo funciona:
  • Declarado: lo que cargó el chofer (campo efectivo_declarado).
  • Esperado: suma automática de remitos cobrados en efectivo del día, − gastos en efectivo (combustible + extras).
  • Δ (diferencia): se calcula al vuelo, no requiere columna nueva.
  • Aprobar: setea status = aprobada + aprobada_por + aprobada_at.
  • Con diferencia: si Δ ≠ 0, el sistema exige nota del admin antes de aprobar.
  • Click en una fila → modal con detalle de remitos + gastos que componen el esperado.

Cambio de schema mínimo: agregar a tabla rendicion los campos status, aprobada_por, aprobada_at, nota_admin.

Cómo funciona:
  • Cada plan tiene trigger_type (km / horas / meses) y intervalo.
  • Se busca el último maintenance_log del camión para ese plan → si no hay, se toma el km/fecha inicial del camión.
  • Cálculo:
    • KM: próximo = último_km + intervalo; alerta si km_actual ≥ próximo − umbral.
    • Meses: próximo = último_fecha + intervalo; alerta si faltan < 60 días.
  • Se guarda en tabla nueva maintenance_alerts generada por un cron/función (o en un view que calcula al vuelo).
  • Registrar service → inserta maintenance_log + resetea el contador.

Umbrales de color: verde > 30%, ámbar 10-30%, rojo < 10% o vencido.

Vista Camión — timeline por unidad

Hoy los datos están organizados por chofer (mis jornadas, mis remitos) o por período. Falta una vista por unidad: "qué le pasó al camión ABC123 este mes". Útil cuando un admin investiga un gasto raro, un km inflado o quiere ver historial antes de mandar el camión al taller.

5

Export PDF de rendición mensual

Botón para descargar un PDF firmable con el resumen del mes: cobros, gastos, neto a rendir, y detalle día por día. Útil para archivo formal y firma cruzada admin-chofer.

¿Cuál seguimos?

Mi orden sugerido (esfuerzo/valor):
  1. Comparativo período anterior — 100% frontend, alto impacto visual. 2-3h.
  2. Export PDF rendición mensual — reusa infra del PDF de remito. 3-4h.
  3. Historial de rendiciones — requiere migración chica (4 campos) + UI nueva. 6-8h.
  4. Vista Camión timeline — requiere agregar screen nueva + queries. 5-7h.
  5. Mantenimiento preventivo — es el más ambicioso: schema + lógica + UI. 10-15h.
